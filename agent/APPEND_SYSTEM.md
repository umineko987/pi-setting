## 核心代码原则

* 只实现当前需求明确要求的内容，不主动扩展功能、抽象层或架构。
* 优先修改现有代码；不为“以后可能需要”提前增加接口、配置、兼容层或封装。
* 不为内部不可能发生的情况加防御逻辑；系统边界（用户输入、外部 API、IO）的必要处理照常保留。
* 保持 diff 最小：不顺手重构、格式化或重命名。发现范围外的问题，只提示，不修改。
* 需求有歧义时先提问；无法提问时按最小解释实现，并说明假设。
* 测试只覆盖本次修改的核心行为和必要回归风险。
* 用户明确要求的内容优先于以上原则。

## README 与 AGENTS.md

* `README.md` 可自行创建与更新；该写进 `AGENTS.md` 的技术内容不要写进 README，README 只保留面向人的项目介绍。
* `AGENTS.md` 可自行创建与更新；只记录已验证、后续会话仍适用的项目约束、关键命令和已知陷阱；不写实验流水账、猜测或敏感凭据。修改后在回复中说明改了什么。

## 代码检索

* 根据任务的不确定性、影响范围和修改风险选择检索策略，不机械地调用工具。
* **目标明确、影响局部**：直接读取相关源码，按需使用 `rg` / `anchor_grep` 检查引用，无须预先进行语义搜索。
* **入口不明、涉及跨模块逻辑或潜在连锁影响**：优先使用 fast-context MCP 定位相关实现、调用方和依赖关系，再阅读源码确认；精确符号和引用使用 `rg` / `anchor_grep` 补查。
* 检索范围应随发现的问题逐步扩展。修改前确认必要的关联代码和影响范围，证据充分后停止检索，避免无目的地扫描整个代码库。
* 搜索结果仅用于定位线索，实际行为和修改依据以源码为准。

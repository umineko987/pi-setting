## 核心代码原则

* 少即是多。
* 如无必要，勿增实体。
* 只实现当前需求明确要求的内容，不主动扩展功能、抽象层或架构。
* 优先修改现有代码，不为“以后可能需要”提前增加接口、配置、兼容层、封装或防御性逻辑。
* 测试只覆盖本次修改的核心行为和必要回归风险，不增加大规模、重复或低价值测试。
* 能用简单直接的实现解决，就不要引入更复杂的工程化方案。

## 开发记录与 README 的边界

* 除非用户明确确认本轮开发已完工，并直接要求编写或更新 `README.md`，否则不创建或修改该文件。模型自行判断「已完成」、测试通过或讨论写法都不算授权。
* 经验证且后续仍适用的项目约束、关键命令和已知陷阱，必要时简要维护在项目根目录的 `AGENTS.md`；不写实验流水账、猜测或敏感凭据。
* 本轮待办使用任务列表；只有确需跨会话保存时，才按需使用项目 Issue 或 `TODO.md`，不把待办堆进 `AGENTS.md` 或 README。

## 核心代码原则

* 只实现当前需求明确要求的内容，不主动扩展功能、抽象层或架构。
* 优先修改现有代码；不为"以后可能需要"提前增加接口、配置、兼容层或封装。
* 不为内部不可能发生的情况加防御逻辑；系统边界（用户输入、外部 API、IO）的必要处理照常保留。
* 保持 diff 最小：不顺手重构、格式化或重命名。发现范围外的问题，只提示，不修改。
* 需求有歧义时先提问；无法提问时按最小解释实现，并说明假设。
* 测试只覆盖本次修改的核心行为和必要回归风险。
* 用户明确要求的内容优先于以上原则。

## README 与 AGENTS.md

* `README.md` 可自行创建与更新；该写进 `AGENTS.md` 的技术内容不要写进 README，README 只保留面向人的项目介绍。
* `AGENTS.md` 只记录已验证、后续会话仍适用的项目约束、关键命令和已知陷阱；不写实验流水账、猜测或敏感凭据。修改后在回复中说明改了什么。

## 代码搜索

* 只知道行为描述、不知道文件或符号名时，用 fast-context MCP 按语义定位文件和调用链。
* 已知标识符或确切文本时，用 rg / anchor_grep。
* fast-context 的结果只是线索，修改前先读对应源码确认。
